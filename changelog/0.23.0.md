## Deutsch

Schneller, flüssiger und ohne Hänger: Trennen geht jetzt sofort, ein stummer Adapter bremst nichts mehr aus, und die Oberfläche startet und reagiert spürbar schneller.

**Keine Hänger mehr**
- Trennen bricht einen laufenden Suchlauf oder Check ab und dauert etwa 2 Sekunden statt bis zu mehreren Minuten
- Antwortet der Adapter gar nicht mehr, kostet eine Runde Live-Werte etwa 4 statt 28 Sekunden, und die Werte werden danach weiter gebündelt abgefragt
- Verbinden über WLAN gibt nach 5 Sekunden auf statt nach bis zu 2 Minuten; Bluetooth LE kann nicht mehr endlos hängen
- Ein gezogenes Kabel oder ein verlorener Adapter lastet keinen Prozessorkern mehr voll aus
- Beim Beenden schließt Caruspex den Adapter sauber, bevor das Programm endet
- Langsame Befehle wie das Teilen eines langen Mitschnitts laufen nicht mehr im Fenster und frieren es nicht ein

**Flüssigere Oberfläche**
- Schnellerer Start: das erste Bild ist früher da, weil nur die sichtbare Seite sofort aufgebaut wird
- Das Protokoll unten kostet während einer Messung nur noch einen Bruchteil der Rechenzeit, auch wenn es offen ist
- Das Fehlercode-Lexikon öffnet beim zweiten Mal in etwa einer Zehntelsekunde statt in über einer Sekunde, die Suche bleibt beim Tippen flüssig
- Live-Werte brauchen im Hintergrund etwa ein Drittel weniger Speicheranlegungen

**Unter der Haube**
- Alle Bibliotheken auf dem neuesten stabilen Stand, Node 26, aktuelle Android-Werkzeuge; zwei ungenutzte Abhängigkeiten entfernt
- Große Quelldateien in übersichtliche Module aufgeteilt, doppelter und toter Code entfernt
- Ein einziger Befehl prüft alles, was auch die automatische Prüfung auf GitHub prüft (`tools/check_all.sh`)
- Die automatische Prüfung vergleicht jetzt auch die erzeugten Datentabellen; das tat sie vorher versehentlich nicht

Hinweis: Die Verbesserungen sind gegen nachgebildete Adapter und Autos gemessen, noch nicht mit echter Hardware.

## English

Faster, smoother and without hangs: disconnecting is now immediate, a silent adapter no longer slows everything down, and the interface starts and responds noticeably faster.

**No more hangs**
- Disconnecting cancels a running scan or check and takes about 2 seconds instead of up to several minutes
- If the adapter stops answering, a round of live values costs about 4 instead of 28 seconds, and the values are still requested in batches afterwards
- Connecting over Wi-Fi gives up after 5 seconds instead of up to 2 minutes; Bluetooth LE can no longer hang forever
- A pulled cable or a lost adapter no longer keeps a processor core at full load
- On exit Caruspex closes the adapter cleanly before the program ends
- Slow commands such as sharing a long recording no longer run in the window and no longer freeze it

**Smoother interface**
- Faster start: the first picture appears sooner, because only the visible page is built right away
- The log at the bottom now costs only a fraction of the computing time during a measurement, even when it is open
- The fault code lexicon opens the second time in about a tenth of a second instead of more than a second, and searching stays smooth while typing
- Live values need about a third fewer memory allocations in the background

**Under the hood**
- All libraries on their newest stable versions, Node 26, current Android tools; two unused dependencies removed
- Large source files split into clear modules, duplicate and dead code removed
- One single command checks everything the automatic check on GitHub checks (`tools/check_all.sh`)
- The automatic check now also compares the generated data tables; before, it accidentally did not

Note: the improvements are measured against simulated adapters and cars, not yet with real hardware.
